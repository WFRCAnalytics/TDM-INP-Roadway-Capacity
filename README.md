# TDM-INP-Roadway-Capacity

Calculating the capacity for roads based on UDOT CCS data by travel demand model
functional type and number of lanes.

Compares observed UDOT continuous count station (CCS) hourly volumes against the
Wasatch Front travel demand model's own per-lane capacity assumptions
(`CAP1HR1LN`, by facility type and lane count), to sanity-check whether the model's
capacity table actually tracks what's observed in the field.

**Live dashboard:** https://wfrcanalytics.github.io/TDM-INP-Roadway-Capacity/
(tables + summary charts over the results below).

## Repo layout

| Path | Contents |
|---|---|
| `data/` | Static input data snapshots (see Data provenance below) |
| `analysis/ccs_link_capacity_analysis.py` | The analysis script -- reads `data/`, writes `output/` and `docs/data/` |
| `output/` | Committed, curated CSV outputs (regenerated by the script; see below) |
| `docs/` | GitHub Pages dashboard (`index.html` + `data/capacity_data.json`) |

## Data provenance

All of `data/` is a static, standalone snapshot copied from the
[WF-TDM-Calibration](https://github.com/WFRCAnalytics/WF-TDM-Calibration) repo. This
repo has **no dependency** on that repo, its `tdm/` submodule, or Cube Voyager --
everything needed to reproduce `output/` and the dashboard lives here.

| File | Source | Notes |
|---|---|---|
| `taz/WFv1000_TAZ.shp` (+sidecars) | `report/data/4-assignhwy/taz/` | TAZ polygons, used only for the `MARGINAL` (mountainous-zone) flag |
| `RegionalBoundary.gpkg` | `report/data/4-assignhwy/` | MPO boundary, used to clip CCS stations to the modeled region |
| `SiteData.csv`, `SiteData_supplement.csv` | `report/data/4-assignhwy/UDOT_VehicleClassificationCounts/` | CCS station locations/metadata |
| `2023 Station 301-431.xlsx`, `2023 Station 501-733.xlsx` | top-level `data/` | Raw hourly-by-lane CCS volume workbooks |
| `Lookup_Speed_Capacity.csv` | `tdm/1_Inputs/0_GlobalData/0_SpeedCap/` (inside the `tdm` submodule) | FT -> per-lane capacity (`CAPLN1`-`CAPLN7`) lookup table |
| `tdm_scenario_C74_links.gpkg` | `tdm/Scenarios/C74/0_InputProcessing/ScenarioNet/scenario - Link.shp` | **Frozen snapshot**, not auto-refreshed. Trimmed to the columns this script needs (`LINKID`, `FT`, `FTCLASS`, `LANES`, `CAP1HR1LN`, `STREET`, geometry) from a 93MB raw attribute table. Sourced from calibration run **C74** (`tdm_ref: calib/C74`) -- a gitignored, per-run scenario output in that repo, so it can't be re-fetched by cloning; if the network needs updating, re-extract from a newer calibration run's `tdm/Scenarios/{run}/0_InputProcessing/ScenarioNet/scenario - Link.shp` the same way (see the script history / ask in WF-TDM-Calibration). |

## Regenerating

```bash
python -m venv .venv
.venv/Scripts/activate   # or source .venv/bin/activate
pip install -r requirements.txt
python analysis/ccs_link_capacity_analysis.py
```

This overwrites `output/*.csv` and `docs/data/capacity_data.json`. Commit both after
reviewing the printed summary -- there's no CI build step; the dashboard is a
pre-built static page, same as the four CSVs are pre-built, curated outputs.

## Excluded stations

Three station sets are dropped from the final tables (kept in
`output/ccs_station_link_capacity_raw.csv` for inspection):
- Stations reading implausibly high (>150% of assumed capacity) even within the
  calibration window -- likely sensor/data issues.
- Bangerter Hwy stations currently coded FT 13/15 (Expressway) -- Bangerter is being
  converted to freeway, so its current FT code may not represent it well.
- Stations inside a mountainous (`MARGINAL=1`) TAZ.

## Publishing the dashboard

`.github/workflows/publish-pages.yml` deploys the committed `docs/` folder on every
push to `main` that touches `docs/**` -- no build step. One manual one-time setting:
in this repo's GitHub **Settings -> Pages**, set **Source: GitHub Actions** (not
"Deploy from a branch").
